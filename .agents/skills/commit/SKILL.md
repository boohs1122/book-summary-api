# 커밋 절차

메시지 형식, 커밋 단위, 사전 검사 명령은 [.ai/rules/git.md](../../../.ai/rules/git.md)를 따른다.
이 문서는 순서만 다룬다.

1. `git config user.email`이 `boohs1122` noreply 주소인지 확인한다. 다르면 멈추고 보고한다
2. 현재 브랜치가 변경 성격에 맞는지 확인한다. 기능 구현은 `feature/*`, 문서·설정은 `main`
3. `git status`와 `git diff HEAD`로 변경 내용과 의도하지 않은 파일이 없는지 확인한다
4. 성격이 다른 작업이 섞여 있으면 커밋 분리를 먼저 제안한다
   - 한 파일에 포맷 변경과 기능 변경이 섞이면 `git add -p`로 나눠 담는다
5. 사전 검사를 실행한다. 실패하면 커밋하지 않고 보고한다
6. 메시지를 작성해 커밋별 파일 목록과 함께 제시하고 승인을 받는다
7. 승인 후에만 스테이징하고 커밋한다
8. push는 사용자가 요청했을 때만 한다

## 확인 사항

- `.githooks/`가 작성자, 비밀 파일, AI 작업 표기, 사전 검사를 다시 검사한다.
  훅이 커밋을 막으면 우회(`--no-verify`)하지 않고 원인을 보고한다
- 훅이 동작하지 않으면 `git config core.hooksPath`가 `.githooks`인지 확인한다
